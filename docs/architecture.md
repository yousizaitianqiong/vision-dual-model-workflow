# 架构说明

## 目标

将图片和短视频转换为视觉模型能够稳定读取的图片输入，再通过两个具有不同职责的视觉模型完成初筛与复核。Dify 负责可视化编排和结果呈现，媒体服务负责格式边界和视频抽帧。

## 组件

| 组件 | 公开 Demo | 真实项目职责 |
| --- | --- | --- |
| 工作流编排 | Dify 1.17.x Workflow DSL | 接收媒体、提示词和输出格式，串联各节点 |
| 媒体处理 | FastAPI + Pillow + FFmpeg | 图片规范化，视频均匀抽取最多 8 帧并生成联系表 |
| 初筛模型 | OpenAI 兼容 Mock | 对应 SenseNova-SI-2B 初筛 |
| 复核模型 | OpenAI 兼容 Mock | 对应 Qwen3-VL-8B 复核 |
| 结果汇总 | Dify Template Transform | 输出详细对比、精简结论或原始结果 |

## 架构图

```mermaid
flowchart LR
    A[图片或短视频<br/>自定义提示词] --> B[FastAPI 媒体预处理]
    B -->|图片 JPEG| C[SenseNova-SI-2B<br/>初筛]
    B -->|视频最多 8 帧联系表| C
    C --> D[Qwen3-VL-8B<br/>复核]
    D --> E[Dify 模板汇总]
    E --> F[结果输出]
```

## 请求路径

1. 用户上传一个图片或视频，并填写自定义提示词；
2. Dify 将文件提交给媒体预处理服务；
3. 图片转为 RGB JPEG，视频按时长均匀抽取最多 8 帧并生成联系表；
4. 初筛模型输出观察对象、风险、依据和待复核疑点；
5. 复核模型重新读取视觉输入，再对照初筛文本；
6. Dify 汇总两个模型的结果并返回最终文本。

## 设计取舍

- 联系表将视频转换为单个标准图片输入，降低工作流和模型服务之间的格式耦合；
- 初筛与复核职责分离，复核模型必须重新查看视觉证据，不能只接受初筛结论；
- Demo 用 Mock 服务验证接口协议；真实模型端点由部署环境配置；
- 输入文件只来自上传内容，服务不执行用户传入的命令，也不代替用户访问任意 URL。
